Select lets people choose from a known list without typing: a country, a currency, a person, a payment method.
It is the field version of the [Dropdown Menu](?path=/docs/components-dropdown-menu--docs): the same rows, with a label,
a hint and the states of Input, so a form reads as one system.

```tsx
<Select label="Country of residence" type="country" options={countries} onChange={setCountry} />
```

## Examples

Every example is a live story. Its steps also run as a test in the **Interactions** tab, so a broken behaviour shows up at once.

### Search a long list

<Canvas of={SelectStories.SearchALongList} />

Countries are a long list, so a search row appears by itself. Typing *po* leaves Poland. Opening the list leaves the cursor in the field, so people can scroll and look first; a click or Tab takes them to the search. Each time the list opens, the search starts empty.

### Choose with the keyboard

<Canvas of={SelectStories.ChooseWithTheKeyboard} />

Tab to the field, ↓ opens the list, ↓ moves, Enter chooses. The blue focus ring appears only when people use the keyboard.

### Choose several

<Canvas of={SelectStories.ChooseSeveral} />

With `multiple`, every row gets a checkbox and the list stays open. The field lists the choices with commas and sums up
the rest (*Payman, Stripe and 3 others*), updating as the field narrows.

From 4 options, **Select all** heads the list, under the search: it chooses every option the search shows, or clears them
when all are chosen, and is half-checked while only some are.

### Clear an optional choice

<Canvas of={SelectStories.ClearAnOptionalChoice} />

An optional field can be emptied again: × appears once something is chosen. A required field has no ×, since it can't be
left empty. Compact Select and Inline Select have no × either: they always hold a value.

### Required in a form

<Canvas of={SelectStories.RequiredInAForm} />

The error appears after people try to send the form, not while they are still filling it in, and goes once they choose.

## Design decisions

What the code adds to the Figma file, and why:

- **Choice order, not list order.** In a multi-select the field keeps the order in which people picked options, as the
  Figma examples ask. When the list overflows, what they picked first stays visible. (PrimeReact would follow the list order.)
- **Search from 11 options.** The Figma guidelines show 9 rows without scrolling and a search row once the list is longer
  than 10. The code applies it by itself; `searchable` overrides it.
- **When a list gets a search.** PrimeReact leaves it to the product. The GRG rule, for every list (Select, Compact Select,
  Inline Select, Filter): more than 10 options, search by itself; lists that come from data and grow (merchants,
  counterparties, currencies), always, with `searchable`, even while short; short fixed lists (status, type), never.
  Dropdown Menu holds actions and has no search: a list long enough to search is a choice, so it is a Select.
- **The search starts empty and waits.** Closing the list clears it, and opening doesn't move the cursor into it.
- **× in every search.** The multi-choice lists get it too (PrimeReact MultiSelect has none). It isn't a Tab stop: Escape
  closes the list and clears the search, and the text can be deleted as usual.
- **Searching doesn't move the list.** The clear icon's place in the search row is kept while it is empty, and the list keeps the width it opened with when shorter options remain. The same for Compact Select, Inline Select and Filter.
- **Over a modal.** Inside a modal the open list is drawn over it, whole, and can reach past its edges; it stays in the modal's markup, so screen readers still reach the options of an `aria-modal` dialog. The same for Compact Select, Inline Select and Filter.
- **One row for every list.** Select, Compact Select, Inline Select and Dropdown Menu share the Figma *Dropdown menu item*,
  so a fix or a new option type reaches all of them.
- **Rows keep their height.** Every row is 40px, with or without the check and with a checkbox in a multi-select too (Figma draws checkbox rows 36px), so ticking a row never makes the list jump.
- **Focus you can see.** Figma draws focus in `primary-soft-200`, which keyboard users can barely see; the code uses the
  system blue ring, and only for keyboard focus.
- **States are behaviour, not props.** Hover, focus and open come from the pointer and the keyboard, so they are tried
  in the examples rather than drawn one by one. Error and disabled are props, and each has its own example.

## Sizes

<Canvas of={SelectStories.Sizes} />

Only the paddings and corners change; the text stays the same size. The floating label **takes no vertical space**: leave 22px above every field in a form layout.

## Accessibility

| Key | What it does |
|---|---|
| Tab | Moves focus to the field; the blue ring shows |
| ↓ or Enter or Space | Opens the list |
| ↑ ↓ | Moves through the options |
| Enter | Chooses the option (in a multi-select, ticks it and keeps the list open) |
| Escape | Closes the list and keeps focus on the field |
| Typing (in the field) | Moves to the option that starts with those letters |
| Tab (list open) | Moves into the search, then to Select all |
| Typing (in the search) | Filters the list |

- The field is a combobox named by its label; the option under the arrow keys is announced.
- The hint and the error are read with the field; an error also marks it as invalid.
- Pictures are decorative: the option names say what is chosen.
