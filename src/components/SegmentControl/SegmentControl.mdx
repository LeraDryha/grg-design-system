Picks one of a few options in a row (Buy or Sell, a period, a filter), or switches between views of the same content.

<Canvas of={SegmentStories.Playground} />
<Controls of={SegmentStories.Playground} include={['role', 'fullWidth', 'iconOnly', 'disabled']} />

```tsx
<SegmentControl aria-label="Order side" fullWidth value={side} onChange={setSide}
  segments={[{ value: 'buy', label: 'Buy', color: 'green' }, { value: 'sell', label: 'Sell', color: 'red' }]} />
```

### Narrow screen

## Design decisions

- **Two roles, one look**: `choice` (a set of options, like radios) and `tabs` (views of content, like Tab Menu).
- **The keyboard**: Tab reaches the control in one step, the arrow keys move and choose, as people expect from radios and tabs. PrimeReact SelectButton only moves the focus with the arrows and doesn't answer Enter, so the control does it.
- **One segment is always selected.**
- **Width**: each segment as wide as its content, or equal segments across the container (`fullWidth`).
- **Focus** uses the system blue ring.

## Accessibility

| Key | What it does |
|---|---|
| Tab | Moves to the selected segment, then out |
| ← / → | Moves to the next segment and selects it |
| Home / End | First and last segment |
| Enter / Space | Selects the focused segment |

- `choice`: a `radiogroup` of `radio`s with `aria-checked`; `tabs`: a `tablist` of `tab`s with `aria-selected`, and the content as a `tabpanel`.
- Known contrast from Figma: an unselected label (`text-soft-500` on `bg-weak-100`) is 4.3:1, just under 4.5:1. `text-subtle-700`, the Hovered colour, would pass.
