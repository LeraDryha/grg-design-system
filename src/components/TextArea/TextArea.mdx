A multi-line text field for feedback, messages and comments, with a label, a character counter, a hint and extra information on the right.
It shares the label, hint, Key: value and states with Input.


## Examples

Every example is a live story. Its steps also run as a test in the **Interactions** tab.

### Write feedback

<Canvas of={TextAreaStories.WriteFeedback} />

The counter shows the count and the limit (*35/40*). `maxLength` is enforced by the browser: typing and pasting stop at the limit.
Without `maxLength` the counter shows only the count.

### Required in a form

<Canvas of={TextAreaStories.RequiredInAForm} />

The error appears after people try to send the form and goes once they write. The border and the counter turn red; screen readers read the message with the field.

### Resize with the keyboard

<Canvas of={TextAreaStories.ResizeWithTheKeyboard} />

The icon at the bottom right is the **resize handle**: drag it down to make the field taller, up to make it shorter.
With the keyboard, Tab to it: ↓ and ↑ change the height by one line (20px), Home and End jump to the smallest and largest size.

### Saved text over the limit

<Canvas of={TextAreaStories.SavedTextOverTheLimit} />

A value from the application can be longer than the limit. The field shows *Character limit exceeded.* instead of cutting saved text. The application must also validate saved values.

## Design decisions

What the code adds to the Figma file, and why:

- **A maximum height of 400px.** From the starting 122px to 400px, about 14 lines. Past that the text scrolls inside the field, so a long message never pushes the rest of the form off the screen. Figma sets no maximum; roughly half a laptop screen is common practice.
- **A resize handle that works without a mouse.** In Figma it's the *16/resize* icon inside the counter. In code it is a focusable handle named *Resize text area*, with a tooltip and arrow keys.
- **The counter is read once, not on every key.** Screen readers hear *153 of 200 characters* with the field.
- **Saved text is never cut.** Text over the limit is shown with an error, not deleted.
- **States are behaviour, not props.** Hovered and Active follow the pointer and focus; error and disabled are props with their own examples.

## Sizes and counter

<Canvas of={TextAreaStories.Sizes} />

Match the size to the Inputs next to it; lg is the default and the size for a standalone field such as a feedback section.
The text (Body-md 14/20), the 10px corners and the 122px starting height stay the same; only the paddings change.

<Canvas of={TextAreaStories.Counter} />

The counter is its own component in Figma. It follows the field: red over the limit or with an error, grey when the field is disabled.

## Accessibility

| Key | What it does |
|---|---|
| Tab | Moves focus into the field, then to the resize handle |
| ↓ ↑ (handle) | Make the field one line taller or shorter |
| Home · End (handle) | Smallest and largest height |

- The label is a real `<label>`, so it stays the field's name even while it is shown as the placeholder.
- The hint, the error and the counter are connected with `aria-describedby`. An error, including going over the limit, sets `aria-invalid`.
- Colours follow Figma. On the hovered field the counter (`text-soft-500` on `bg-weak-100`) reaches 4.3:1, just under the 4.5:1 for text.
