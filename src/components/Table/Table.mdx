Rows of data to compare and act on: assets, orders, transactions, members. Columns sort, rows can be selected and opened, and every cell is a system component.

<Canvas of={TableStories.Playground} />

```tsx
<Table
  aria-label="Assets"
  rows={assets}
  rowKey={row => row.id}
  columns={[
    { id: 'asset', header: 'Asset', sortValue: row => row.name, cell: row => <TableText priority="leading" title={row.name} description={row.code} /> },
    { id: 'amount', header: 'Amount', sortValue: row => row.amount, cell: row => <TableText title={row.amount} /> },
  ]}
  actions={row => <Button variant="text" size="xs">Withdraw</Button>}
/>
```

## Design decisions

- **Four kinds of rows.** A table to read has no row press and no chevron. When a row has details, the whole row opens them and a chevron ends the row (`onRowOpen`); when it has its own page, the row and the chevron are a link (`rowHref`); when a little more belongs right under it, the row opens in place, with a chevron down or up (`expansion`, PrimeReact row expansion). A single link inside a cell, such as an ID, is a Link.
- **Sorting** cycles ascending → descending → original order, one column at a time, as Carbon and Material do. The icon shows both arrows while unsorted, one while sorted; screen readers hear the order.
- **Sticky columns.** The selection and the first column stick to the left, the actions (or the chevron) to the right, with the Figma table shadows while something hides under them.
- **Scroll arrows** are for the mouse; the keyboard and screen readers scroll the table itself, which takes focus.
- **Long text** ends with "…" and shows in full in a tooltip, only when it is actually cut.
- **Hover** is `bg-muted-50` on the whole row.
- **Loading** isn't in Figma: grey placeholder rows (see [Contributing/Tokens](?path=/docs/contributing-tokens--docs)).
- **Phones** scroll the table sideways; the columns never shrink into "…" headers. When the stuck columns would cover more than half the table, only the left ones stay and the actions scroll with the rest.

## Row actions

What goes in the actions column, so every table in the product does it the same way:

- **Actions every product has: an Action Button with a tooltip.** Edit (pencil), delete (trash, red), download, copy. The icon is known; the tooltip and the screen reader name say what and whose: *Delete Hana Sato*.
- **Actions of this product: a text button.** *Convert*, *Deposit*, *Withdraw*, *Deactivate*, *Transfer ownership*. No icon says these, so the word does. A text button that removes or stops something is red (*Deactivate*).
- **More than three actions, or a narrow card: a menu.** One Action Button with three dots opens a Dropdown Menu with all of them, as on the Dashboard's balance card.
- **An action that can’t be done stays and is disabled**, so the columns don’t jump: *Convert* and *Withdraw* on an empty balance.
- **Opening the row is not an action.** The chevron and the row press open details (see Four kinds of rows); they never sit among the buttons.

## Accessibility

| Key | What it does |
|---|---|
| Tab | Moves to the table (to scroll it), the headers that sort, then the controls in the rows |
| Enter / Space on a header | Sorts by that column |
| ← / → on the table | Scrolls it sideways |

- A real table: screen readers read the header of each cell, and `aria-sort` on the sorted column.
- Checkboxes are named after the row (*Select Rudy Kozey*), the chevron too (*Open Rudy Kozey*). An expanding row's chevron is *More about …*, says whether it is open (`aria-expanded`) and points to the part it opens.
- Loading sets `aria-busy`.
