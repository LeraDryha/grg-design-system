# Checkbox

A box to turn an option on or off, on its own or with a label. With a label (`CheckboxLabel`, Figma *Checkbox label*)
it can carry a sublabel, a description and a link, and flip to the right for lists.

<Canvas of={CheckboxStories.Playground} />

```tsx
<CheckboxLabel label="I agree to the Terms of Service" checked={accepted} onChange={setAccepted} />
```

## Examples

Every example is a live story. Its steps also run as a test in the **Interactions** tab.

### Select all

<Canvas of={CheckboxStories.SelectAll} />

A parent checkbox selects or clears all items. While only some are selected it shows the indeterminate dash, announced as *mixed*.

### Accept the terms

<Canvas of={CheckboxStories.AcceptTheTerms} />

A required choice that is missing: the checkbox turns red and a message under the label says what to do. Show it after people try to send the form, not while they are still filling it in. Lists and tables don't need it: there is no wrong choice there.

### Explain an option

<Canvas of={CheckboxStories.ExplainAnOption} />

A **sublabel** (*(Optional)*, *(Recommended)*), a **description** and a **link**. The whole label is clickable; the description is read with the checkbox.

### Checklist on the right

<Canvas of={CheckboxStories.ChecklistOnTheRight} />

Flipped (Figma *Flip*): the checkbox on the right, for lists where the text comes first. The last row is disabled.

### Remove something

<Canvas of={CheckboxStories.RemoveSomething} />

Destructive: red in every state, for a choice that removes something. For a missing required choice, use the error instead.

## Design decisions

What the code adds to the Figma file, and why:

- **Error and Destructive are split.** Figma has one Destructive switch for both meanings. The code uses `destructive` for the look of a removing choice, and `error` (with a label) or `invalid` for a mistake, which screen readers hear as invalid. The error message is the same Hint text as under Input and Select.
- **Indeterminate on the native checkbox.** PrimeReact 10 has no indeterminate state, so the component sets it on the native checkbox; screen readers announce *mixed*.
- **Focus you can see.** Figma draws a 4px `primary-soft-200` frame; the code uses the system blue ring.
- **States are behaviour, not props.** Hovered and Pressed (Figma *Active*) come from the pointer; try them in the examples.

## Selection and sizes

<Canvas of={CheckboxStories.Selection} />

<Canvas of={CheckboxStories.Sizes} />

The label stays Body-md/Medium 14/20 in both sizes; the checkbox sits in a frame as tall as the first line, so it lines up with the label.
The gaps follow Figma: 8px between the checkbox and the text, 4px to the sublabel, 2px to the description, 10px to the link.

## Accessibility

| Key | What it does |
|---|---|
| Tab | Moves focus to the checkbox; the blue ring shows |
| Space | Switches it on or off |

- It is a native checkbox: screen readers call it a checkbox, and it works in forms.
- With a label, the label names it. A checkbox on its own needs `aria-label`.
- An error is not shown by colour alone: the message is connected with `aria-describedby`, and `aria-invalid` is set.
- Colours follow Figma. The empty ring (`stroke-base-300`) reaches about 1.5:1 against the surface, under the 3:1 WCAG asks for controls; the label next to it helps people find it.
